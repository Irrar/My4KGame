# 谱面规范 & 工具

> 这份文档写给"继续写谱 / 改谱"的人。踩过的坑都写在前面，照着做就不会再出
> "Hold 还没松手，同轨又来一个 tap" 这种让玩家打不了的谱。

---

## 一、三条硬规则（违反必出 bug）

| # | 规则 | 违反的后果 |
| --- | --- | --- |
| 1 | **同一轨道，Hold 持续期间不允许有任何其它音符** | 那段时间按键会被吞（见下方原理），谱面上的音符打不出来 → 必 MISS |
| 2 | **Hold 结束后，同轨至少留 140ms 空白** | 玩家来不及松手再按，实际打不出来（"反盾"太紧） |
| 3 | **同一时刻、同一轨道不允许有两个音符** | 叠在一起，只能判到一个 |

### 为什么规则 1 是致命的

`NoteSpawner.ResolvePress()` 第一件事就是：

```csharp
// 该轨道已有长按按住时，不再响应新的按压（简单模型）
if (_held[lane] != null) return Judgement.None;
```

也就是说 **Hold 按住期间，这条轨道的任何新按键都直接返回"空打"**。
如果谱面在 Hold 期间塞了一个 tap，玩家无论怎么按都打不中 —— 这不是难度，是 bug。

物理上也说得通：一根手指按着长条，不可能同时再点一下同一根手指所在的轨道。

## 二、工具：`tools/chart_tools.py`

```bash
# 只体检（不改文件）
python tools/chart_tools.py

# 修 Hold 冲突（所有谱面），只预览不写回
python tools/chart_tools.py --repair

# 修冲突 + 只给 Expert 重排键型，并且真的写回
python tools/chart_tools.py --repair --patterns expert --apply
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--repair` | 把落在 Hold 区间内 / 贴太近的音符**挪到其它空轨道**；实在没位置才删 |
| `--patterns expert` \| `all` \| `none` | 键型重排范围（只动**连续单点**段落） |
| `--apply` | 真的写文件；不加就是预览 |
| `--root <工程目录>` | 指定工程根（默认脚本上一级） |

**它绝不动时间轴**：所有 `time` / `duration` 原样保留，只改 `lane`。
所以作者的采音不会被破坏，改的只是"用哪根手指打"。

体检输出示例：

```
chart                                     notes  holds  conflicts    bpm    key
InYourBlueEyes_Expert.json                  423     66          0    145   time
WorldsEndBLACKBOX_Expert.json               442    112          0    205   time
```

## 三、键型：交互 / 梯子 / 楼梯

参考《下落式音游齐民要术·排列》：<https://electrowind.github.io/VSRG-4K-wiki/pattern/pailie/>

| 键型 | 英文 | 4K 写法 | 手感 |
| --- | --- | --- | --- |
| 交互 | trill | `0 1 0 1` / `2 3 2 3` / `0 3 0 3` | 两指交替，高速下最稳 |
| 梯子 | rail / ladder | `0 1 2 3` / `3 2 1 0` | 一只手顺着轨道滑过去 |
| 楼梯 | staircase | `0 1 2 3 2 1` / `3 2 1 0 1 2` | 到顶/到底后折返，读谱有明确方向感 |

工具的做法：

- 把"连续单点"切成段；**段内不能有双押、不能夹 Hold**（Hold 会打断手感，键型不该跨过去）；
- 每段随机固定一个**交互对**（`0-1` / `2-3` / `0-3` / `1-2`），段内交替；
- 段长 ≥4 时插入一次**梯子**，≥6 时插入一次**楼梯**，方向每段随机；
- 目标轨道如果正被 Hold 占用，就退化成"挑一条空轨道"，**不硬塞**；
- 双押保持原样（避免把"对拍 / 对切"改成乱序）。

**采音原则**：工具只改轨道，不改时间。想加/删音符、改节奏，请人工按音乐来，
改完再跑一次 `--repair` 体检。

## 六、Master（大师）难度是怎么生成的

Master 不是手写的，是用 `tools/make_master.py` 从同曲最难谱面**加密**出来的，
规则固定、可复现：

```bash
python tools/make_master.py            # 生成 3 首 Master 并写盘
python tools/make_master.py --dry-run  # 只看统计
```

### 加密逻辑

| 步骤 | 做法 |
| --- | --- |
| ① 采音锚点 | 直接把 `*_Expert`（Neon Pulse 用 `*_Hard`）的**所有时间戳**当锚点，原样保留 |
| ② 真实音头 | 有 WAV 的曲子（Neon Pulse）额外做频谱通量 onset 检测，把音头并进候选 |
| ③ 网格加密 | 锚点前后 16 分、全曲 8 分、再兜底 16 分，作为候选 |
| ④ 密度控制 | 按「最近 3 秒内已放音符数 / 3」算局部密度，达到目标就不再塞（防止变成纯 16 分流） |
| ⑤ 补洞 | 任何超过 `max_gap` 的空档用 8 分音符填上 —— **不存在整屏空白的休息段** |
| ⑥ 键型 | 交互 / 梯子 / 楼梯 每 6 个音换一次；小节首随机双押（对切） |
| ⑦ 体检 | 跑一遍 `chart_tools.validate`，冲突/重复必须为 0 |

### 三首 Master 的实际参数

| 曲目 | BPM | 基准 | 音符数（基准） | 平均密度 | 最大空档 |
| --- | --- | --- | --- | --- | --- |
| Neon Pulse | 120 | Hard 223 | 420（1.9×） | 5.85 音符/秒 | 375 ms |
| World's end BLACKBOX | 205 | Expert 442 | 1242（2.8×） | 7.91 音符/秒 | 580 ms |
| in your blue eyes | 145 | Expert 423 | 1396（3.3×） | 6.48 音符/秒 | 517 ms |

> 密度上限是**可以调**的：`tools/make_master.py` 顶部 `SONGS` 里的 `nps`（目标音符/秒）、
> `max_gap`（最大空档）、`min_gap`（同轨最小间距）、`chord`（双押概率）。
> 觉得太简单就把 `nps` 往上调 0.5~1，重新生成即可 —— 时间锚点不变，只是更密。

### 为什么不用纯 16 分铺满

205 BPM 的 16 分是 73ms 一个音，全程铺满 ≈ 13.7 音符/秒，人打不了，
而且和"采音"脱节（安静段也被塞满）。所以改成"跟着锚点走 + 密度上限"：
**热闹的段落自动更密，安静的段落只保留低频度过门，但不会出现空屏**。

## 七、曲子开头的静音（重要）

实测（编辑器菜单 `My4KGame → 12. 测量音频前奏`）：

| 曲子 | 第一个有声位置 | 处理 |
| --- | --- | --- |
| Neon Pulse | 0.00s | 原样播放 |
| World's end BLACKBOX | 1.23s | 跳过前 1.20s |
| in your blue eyes | 12.61s | 跳过前 12.58s |

不处理的后果：按 ▶ → 倒计时结束 → **再干等 1.2 秒（或 12.6 秒）才出声**，
而这段时间音符已经在落了，看起来就是"音符比音乐先出现"。

处理方式（`Assets/Scripts/Core/AudioTimeline.cs`）：

1. 播放时把 `AudioSource.time` 定位到表里的偏移，再从那里起播；
2. 所有音符的判定时间**整体前移同样的量**（`ChartLibrary` 里烘焙时减掉），
   所以音符和音乐的相对关系一点没变，采音不受影响；
3. 落在被跳过的那段静音里的音符会被丢弃（它们本来就没有音乐可对）。

**加新歌时**：先跑菜单 `12. 测量音频前奏`，把得到的秒数填进 `AudioTimeline` 的表里，
保证取值**比首个音符略早一点点**（约 10~30ms），否则踩在第一声上的那个音符会被算成负数丢掉。
