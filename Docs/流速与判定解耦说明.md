# 流速可调、判定不变 —— 实现说明与验收报告

> 对应需求：《音游「流速可调、判定速度不变」实现需求说明》
> 工程：My4KGame（Unity 2022.3.62f3c1）
> 结论：**判定归时间、视觉归流速**已落地，8 项验收全部通过（见第 7 节实测输出）。

---

## 1. 一句话架构

```
        ┌──────────────────────────── 判定轨道（时间） ────────────────────────────┐
谱面 JSON │ ChartLibrary 计算一次 judgeTimeMs（毫秒，之后不可变）                      │
          │            ↓                                                            │
          │ NoteData.JudgeTimeMs ──→ NoteSpawner.ResolvePress(按键时间ms)             │
          │                              ↓                                          │
          │                     GameManager.JudgeMs(Δms) ← 固定窗口 40/80/120/140ms   │
          └─────────────────────────────────────────────────────────────────────────┘
                                     ▲ 只共享"歌曲时钟"，不共享位置/流速
                                     │
        ┌──────────────────────────── 视觉轨道（流速） ────────────────────────────┐
          │ ScrollSpeedTrack（系数 0.5x~4x）                                          │
          │   secondsAhead = judgeTimeMs/1000 − SongTime     ← 与流速无关              │
          │   travelSeconds = 2.0 / coefficient              ← 流速只影响这里           │
          │   y = lerp(判定线Y, 出生点Y, clamp01(ahead/travelSeconds))                   │
          └─────────────────────────────────────────────────────────────────────────┘
```

两条轨道之间**只有一个单向数据流**：判定时间戳（只读）→ 视觉映射。
反向没有任何通路：`ScrollSpeedTrack` 不持有 `NoteData`，也不存在"把位置写回判定"的接口。

## 2. 关键数据结构

### 2.1 判定时间戳（不可变）

`Assets/Scripts/Chart/NoteData.cs`

```csharp
public class NoteData
{
    public float time;      // 秒（兼容旧谱面格式）
    public float beat = -1f;// 可选：用拍定位（0 = 第 0 拍）

    private double _judgeTimeMs = double.NaN;          // 加载时烘一次
    public double JudgeTimeMs => double.IsNaN(_judgeTimeMs) ? time * 1000.0 : _judgeTimeMs;
    public double JudgeTimeSeconds => JudgeTimeMs / 1000.0;

    public void BakeJudgeTimeMs(double judgeTimeMs)    // 全工程只有 ChartLibrary 调它
    {
        _judgeTimeMs = judgeTimeMs;
        time = (float)(judgeTimeMs / 1000.0);
    }
}
```

- 计算发生在 `ChartLibrary.Parse()`，**一次**：`judgeTimeMs = (beat ? chart.BeatToMs(beat) : time*1000) + offset*1000`
- 之后：调速不改、暂停不改、视觉位置不回写。`BakeJudgeTimeMs` 的调用点在工程里只有 1 处。

### 2.2 视觉流速参数

`Assets/Scripts/Core/ScrollSpeedTrack.cs`（单帧映射）+ `Assets/Scripts/Core/ScrollSpeedState.cs`（全局数值）

```csharp
// 全局唯一数据源：主界面卡片、游戏内悬浮窗、视觉轨道都只认这一个值
public static class ScrollSpeedState
{
    public const float MinValue = 1.00f, MaxValue = 10.00f, Step = 0.25f;
    public static event Action<float> Changed;      // 谁改都会广播，两边 UI 自动同步
    public static float Value { get; }              // 1.00 ~ 10.00，已对齐 0.25
    public static float Coefficient => ScrollSpeedTrack.ValueToCoefficient(Value);
    public static void Set(float value, bool save = true);   // 自动写 PlayerPrefs
    public static void Adjust(float delta);                  // ±0.25
}
```

```csharp
public sealed class ScrollSpeedTrack
{
    public float BaseTravelSeconds { get; }    // 1x 时走完全程的秒数（2.0）
    public float TravelSeconds => BaseTravelSeconds / Mathf.Max(0.01f, AppliedCoefficient);

    public float SecondsAheadToY(float secondsAhead)   // ★ 视觉唯一出口
    {
        float progress = Mathf.Clamp01(secondsAhead / TravelSeconds);
        return Mathf.Lerp(PlayfieldLayout.JudgeLineY, PlayfieldLayout.SpawnY, progress);
    }
}
```

它**不认识** `GameManager`、`NoteData`、判定窗口、连击 —— 只有上面这几个字段和一个纯函数。

档位映射也放在这个类里，因为它是"视觉"的一部分（判定侧完全不需要知道档位）：

```csharp
public static float LevelToCoefficient(float level) =>
    Mathf.Pow(2f, (Mathf.Clamp(level, 1f, 10f) - 5.5f) / 4.5f);   // 1档=0.5x, 5.5档=1.0x, 10档=2.0x
public static float CoefficientToLevel(float coefficient) => ...    // 反函数，用于回显
public static float SnapLevel(float level) => ...                   // 对齐到 0.25
```

### 2.3 判定窗口（固定，与流速无关）

`Assets/Scripts/Core/GameManager.cs`

```csharp
public double PerfectWindowMs => perfectWindow * 1000.0;   // 40ms
public double GreatWindowMs   => greatWindow   * 1000.0;   // 80ms
public double GoodWindowMs    => goodWindow    * 1000.0;   // 120ms
public double MissWindowMs    => missWindow    * 1000.0;   // 140ms
```

这四个属性只从 Inspector 的秒数派生，**没有任何流速乘子**。

## 3. 渲染位置映射

`Assets/Scripts/Gameplay/NoteController.cs`

```csharp
float secondsAhead = ScrollSpeedTrack.SecondsAheadOf(Data.JudgeTimeMs, songTime); // 判定时间戳 − 歌曲时钟
float y = scroll.SecondsAheadToY(secondsAhead);                                   // 流速只在这里生效
transform.position = new Vector3(LaneToX(Data.lane), y, 0f);
```

同一时间差 `0.5s`、不同流速下的实测视觉位置（判定线 Y = −4，出生点 Y = 6）：

| 流速 | TravelSeconds | progress = 0.5 / travel | 视觉 Y | 离判定线距离 |
| --- | --- | --- | --- | --- |
| 0.5x | 4.00s | 0.125 | −2.75 | 1.25 |
| 1.0x | 2.00s | 0.250 | −1.50 | 2.50 |
| 2.0x | 1.00s | 0.500 | +1.00 | 5.00 |
| 4.0x | 0.50s | 1.000 | +6.00 | 10.00 |

**时间差没变，变的只是"这段时间画多远"。** 2x 的距离正好是 1x 的两倍（自动化测试里断言的正是这条）。

### 生成提前量也跟着视觉走（但不影响判定）

`NoteSpawner.SpawnDueNotes()`：`if (secondsAhead > scroll.TravelSeconds) break;`
流速快 → 提前量小（音符只在屏幕上方一小段路）；流速慢 → 提前量大（更早出现在屏幕外）。
它只决定"什么时候创建这个 GameObject"，不参与任何判定计算。

## 4. 判定逻辑

### 4.1 入口

```csharp
// NoteSpawner.cs —— 唯一的判定入口
public Judgement ResolvePress(int lane, double pressTimeSeconds)
{
    double pressTimeMs = pressTimeSeconds * 1000.0;

    foreach (note in 场上同轨道、还活着的音符)
    {
        double deltaMs = pressTimeMs - note.Data.JudgeTimeMs;   // 只做时间差
        if (Math.Abs(deltaMs) > game.GoodWindowMs) continue;    // 固定窗口
        取 |deltaMs| 最小的那个作为命中目标；
    }

    return game.JudgeMs(bestDeltaMs);   // 固定窗口 → 等级
}
```

```csharp
// GameManager.cs
public Judgement JudgeMs(double deltaMs)
{
    double abs = Math.Abs(deltaMs);
    if (abs <= PerfectWindowMs) return Judgement.Perfect;
    if (abs <= GreatWindowMs)   return Judgement.Great;
    if (abs <= GoodWindowMs)    return Judgement.Good;
    return Judgement.None;
}
```

### 4.2 三条硬约束（代码级可核查）

| 约束 | 落点 |
| --- | --- |
| 判定不读屏幕坐标 | `ResolvePress` / `JudgeMs` 里没有出现 `transform`、`position`、`localPosition`（冒烟测试还会把音符挪到 y=40 再判一次，结果仍为 PERFECT） |
| 判定不乘流速系数 | `JudgeMs` 的参数只有 `deltaMs`；`PerfectWindowMs` 等由秒数直接换算。`GameManager.Scroll` 只被 `Update`、`NoteSpawner.SpawnDueNotes`、`HudView`、`MenuView` 使用 |
| 调速不重建判定时间轴 | `SetScrollSpeed()` 的全部副作用：改 `ScrollSpeedTrack` 里的 2 个 float + 存 PlayerPrefs + 发事件。`chart.notes` 一个字节都不动 |

MISS 判定同样只看时间：`NoteController` 里 `songTime*1000 − JudgeTimeMs > MissWindowMs`。

## 5. 怎么用

| 入口 | 说明 |
| --- | --- |
| **主界面**：音符流速卡片 | 卡片式：大字号居中数值 `5.50` + 左右箭头 `◀ ▶`，每次 **±0.25**；卡片下方保留实时下落预览 |
| **游戏内**：左下角半透明悬浮窗 | `◀ 5.50 ▶` + “每次 0.25”，不做预览图，随时快速调 |
| 游戏内键盘 | `↑` / `↓` 每次 ±0.25；`PageUp` / `PageDown` 每次 ±1.00 |
| 数值范围 | **1.00 ~ 10.00**，步长 **0.25**（主界面与游戏内完全一致） |
| 提示文案 | “每次调整0.25，只改视觉，不影响判定” |
| 数据同步 | 主界面与游戏内共用 `ScrollSpeedState`（全局单例）：一处改动，另一处通过 `Changed` 事件立刻同步 |
| 持久化 | `PlayerPrefs["My4KGame.ScrollSpeedValue"]`，下次启动沿用；菜单 10 可重置 |

### 数值 ↔ 系数映射

```
系数 = 2 ^ (2 × (数值 − 5.50) / 4.50)      // 等比，范围 ×0.25 ~ ×4.00
数值 = 5.50 + log2(系数) × 4.50 / 2        // 反函数，用于回显
```

| 数值 | 1.00 | 3.00 | 5.50 | 8.00 | 10.00 |
| --- | --- | --- | --- | --- | --- |
| 系数 | ×0.25 | ×0.46 | ×1.00 | ×2.16 | ×4.00 |
| 一屏时间（2.0 / 系数） | 8.00s | 4.32s | 2.00s | 0.93s | 0.50s |

**5.50 正好是 1.00~10.00 的中位**，也就是原来的手感；往上调更快、往下调更慢，两边幅度对称。

> **为什么范围要做到 0.25x ~ 4x**：如果只到 0.5x~2x，37 个 0.25 步每步只差 **3.9%**，
> 按一下几乎看不出变化 —— 这就是最初“调了像没调”的真正原因（不是没生效，是步长太小）。
> 现在每 0.25 = **×1.08**，一格就能看出来；一次调 1.00（PageUp/PageDown）= **×1.36**，非常明显。

> 为什么用按钮不用滑条：滑条只有那根 18×26 的手柄能拖（轨道本身不接收拖拽），
> 很容易出现“拖了没反应”；而调速/校准本来就是离散量，箭头/按钮更精确，也能按住连发。
